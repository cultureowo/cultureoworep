## Умови

У кожному запуску 50 с навантаження, у k6 до 5 с на завершення. Baseline: 1 користувач. Load: 0 → 10 за 10 с, потім 40 с на 10. Stress: 0 → 10 → 25 → 50 за 30 с, потім 20 с на 50. Сценарій однаковий: створення клієнта, посилки, відправлення, читання відправлення; пауза 1 с. API, PostgreSQL та генератор навантаження працюють на одному комп’ютері; запуски послідовні. Метрики охоплюють весь запуск, включно з розгоном. Запити/с враховують усі HTTP-запити.

## Інтерпретація

Порівнюйте навантаження в межах одного інструмента: зростання requests/s показує збільшення обсягу роботи; зростання p95 означає погіршення затримок найповільніших запитів. Якщо stress до 50 користувачів проходить критерії, межа стійкості не знайдена. Зниження затримок у load відносно baseline може пояснюватись прогріванням і варіаціями середовища; ці причини окремо не вимірювались.

k6 задає сценарій, checks і thresholds у JavaScript та повертає ненульовий exit code при їх порушенні. JMeter використовує JMX, HTTP samplers, JSON extractors і assertions; runner додатково оцінює p95 < 500 мс та error rate < 1%. Його error rate включає помилки assertions. k6 має окремі HTTP error rate і request_errors. Додатковий k6 threshold checks=100% суворіший за загальну межу помилок 1%.

Профілі близькі, але не ідентичні: JMeter запускає потоки дискретно, stress складається з трьох груп; scheduler може зупинити потік між HTTP-запитами. k6 дає 5 с на завершення ітерації. JMeter throughput вимірюється між першою та останньою HTTP-вибіркою, а k6 — за тривалістю запуску; остання пауза може вплинути на порівняння. JMeter elapsed та k6 http_req_duration мають різні правила врахування встановлення з’єднання, тому невеликі відмінності не доводять різну швидкість самого API.

БД між цими запусками не очищалась; кількість записів і стан кешів різні. Це обмежує точність порівняння. Короткі 50-секундні тести придатні для навчальної демонстрації, але не підтверджують тривалу стабільність системи. Для точнішого порівняння потрібні однаковий початковий набір даних та повторні вимірювання. Старі довгі запуски збережені як історія; таблиця використовує останні завершені результати.
